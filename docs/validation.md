# 검증 결과 — 2026-10-07

## PC별 경로 설정 변경
- 고정 파일명은 유지하고 폴더를 `config.local.json`으로 분리했다. `configure-target.cmd`의 선택 창 또는 `configure --target-dir`로 설정한다.
- 공통 설정 로더를 수동·미리보기·예약 등록에서 사용하고, PC별 경로까지 반영한 설정 지문으로 사이트 검증 여부를 확인한다.
- 현재 PC는 기존 파일 폴더로 설정을 이관했다. 운영 Excel 파일은 수정하지 않았다.
- 경로 설정 테스트 8개를 추가했다: 새 PC 미설정, 공통 적용, 없는 파일 거절과 기존 설정 보존, 환경 변수/상대 경로, 미정의 변수, 경로 변경 시 검증 무효화, 별도 설정 파일, 이전 전체 경로 호환.
- 기존 12개를 포함한 총 20개 단위 테스트가 통과했다. 새 설정으로 실제 원본 미리보기 결과도 기존 73행을 `already_present`로 확인했다. PowerShell 구문 검사와 로컬 설정 Git 제외 확인도 통과했다.

## 남은 운영 검증
- 로그인 입력 필드와 프레임은 실제 사이트에서 확인했지만, 자격 증명 미등록으로 인증 이후 목록 탐색·다운로드를 검증하지 못함.
- 사이트 어댑터는 첨부 화면의 HTML 테이블 열 순서를 기준으로 작성. 실제 로그인 후 `verify-site`로 검증·필요시 조정해야 함.
- `.xls` 원본 읽기 경로는 구현했으나 실제 `.xls` 샘플로는 검증하지 않음.
- Windows 정기 작업은 아직 등록하지 않음. `check-ready`가 사이트 검증 미완료를 정상적으로 감지함.

로컬 `register-credentials.cmd`를 실행해 로그인 정보를 저장한 뒤 `verify-site`를 통과시키고 정기 작업을 등록한다. 비밀번호를 채팅이나 코드에 적지 않는다.
